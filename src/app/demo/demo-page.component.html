Cell flash on change — Usage guide

Storybook-style notes: how to use the directives correctly, what to avoid, and a live demo of the most common silent failure (missing trackBy).

Usage

{{ usageSnippet }}

flashDurationMs is optional — defaults to 10 000 ms. Swap appFlashOnChangeCss for appFlashOnChangeWaapi to use the Web Animations API variant; the public API is identical.

The trackBy gotcha — see it live

Both tables below render the SAME usageRows array. Click "Mutate one cell" — only the table with trackBy flashes. The other rebuilds every <tr> on each emission, so every cell directive sees its value as a "first emission" (no flash). This is the silent failure you'll hit on real websocket-driven tables.

With trackBy — flashes correctly

{{ col }}
#{{ row.id }} {{ row.values[col] }}

Without trackBy — never flashes

{{ col }}
#{{ row.id }} {{ row.values[col] }}

Do

  • Bind a primitive: string, number, boolean, or null.
  • Set trackBy on every enclosing *ngFor / mat-table / virtual scroll.
  • Put the directive on the cell itself (e.g. <td>) — not on a wrapper.
  • Trust the default 10 s duration; only override for short-lived UIs.
  • Use [appFlashOnChangeCss] as the safe default. Reach for [appFlashOnChangeWaapi] only if you measure a perf win in your specific table.

Don't

  • Pass an object/array — different references always trigger a flash, so every emission would flash.
  • Skip trackBy in *ngFor — every immutable update destroys the directive, suppressing every flash.
  • Put both [appFlashOnChangeCss] AND [appFlashOnChangeWaapi] on the same element — they'd double-animate.
  • Add it to <input> / form controls — animating their background fights browser-native styling. Wrap in a <div>.
  • Add it to a cell whose natural background is already amber — the flash will be invisible.
  • Rely on it for accessibility — the directive does NOT announce changes to screen readers.

Pre-flight checklist

  • Bound value is a primitive (string / number / boolean / null).
  • trackBy set on every enclosing list iterator.
  • Host element accepts background-color cleanly (not a form input, not already amber).
  • Parent component's change detection fires when the value changes (OnPush + new input ref / event / async pipe / markForCheck).
  • Only one of the two directives per element.
