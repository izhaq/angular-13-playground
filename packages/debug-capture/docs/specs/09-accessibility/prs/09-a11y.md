# 09 — Accessibility

Spec: [`../spec.md`](../spec.md) (S09-01 … S09-05). Plan: [`../plan.md`](../plan.md).
Branch `claude/dc-v2-s09-a11y` → one PR into `claude/air-gapped-debug-logging-zkn1nr`.

## Goal

Prove the whole panel against the keyboard map, forced colours and reduced
motion. Two gaps: the banner's warning bar is only a shadow, so forced
colours drop it, and each view's "no match" block was visible on the first
paint next to "nothing yet".

## Owned paths

See the plan. Nothing in the loader. Nothing in the host app.

## Public API

No new exports. `FRAME_CSS` gains one `@media (forced-colors: active)` rule.

## Behaviour

S09-01 is a Playwright walk on the hostile host, not a new key handler.
S09-02 replaces the banner's inset shadow with `border-inline-start: 2px solid CanvasText`
inside `@media (forced-colors: active)`, and sets `box-shadow: none` there.
S09-03 and S09-04 read computed style on the live panel under
`prefers-reduced-motion: reduce` and `forced-colors: active`.

## Required specs

- `frame.spec.ts`: `FRAME_CSS` contains the forced-colours banner rule.
- e2e `panel-a11y`: the §4.12 walk (no mouse), host listeners stay quiet,
  focus returns to the page input; a 4xx row still has its word and icon;
  the capture-off banner's start border is 2 px with no shadow; a keyboard
  focus ring is 2 px; transition and animation compute to none.

## Verification

`npm run check` from `packages/debug-capture`. Report the spec count, the e2e
count and the size numbers. The banner unit spec must fail once before the
CSS rule exists.

## Out of scope

S-10 (hosts, performance, packaging). The playground. v1 download / copy /
clear chords. Size-budget changes.
